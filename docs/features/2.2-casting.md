# 2.2 — Casting

Requirements: **C4** (cast dancers with an optional role), **C5** (circles on the 2D plan with name, role or both as the label; the 3D ballerinas are plan 9.1), **C6** (color by dancer or by role), **C14** (cast list with a count), **B5** (a removed dancer's spot stays as a placeholder).

Done when: cast dancers with roles; the cast list shows how many dancers; label and color modes switch; a removed dancer's spot stays as a placeholder.

Screens: `CastList`, the cast sidebar of `DanceEditorIPad` (load the `living-stage-design` skill).

## Decisions

- **Each dance has a first figure from the start.** It is created together with the dance (`figures: { create: { order: 0 } }`), and the migration backfilled one for older dances. Positions are saved in it, so plan 2.3 builds on real data instead of throwing a layout away.
- **New cast members wait in the left wing.** `nextWingSpot` (`packages/shared/src/figure.ts`) picks the first free of 10 spots down the left wing (x = −0.0625, y = 0.05, 0.15, … 0.95). Once all ten are taken, spots are shared from the top.
- **A dancer is cast at most once per dance.** Unique `(danceId, dancerId)`. A second cast answers 409 `already_cast`.
- **Role colors are automatic (C6).** Each distinct role takes the next color from `dancer-1` to `dancer-11` in the order roles first appear in the cast, starting over after 11. Roles that differ only in case are one role, shown with the first spelling. Dancers with no role are `dancer-12` (stone), which the design keeps for "no role". An open spot stays a dashed ring with no fill in both color modes. No color picker, no `DanceRole` table, no `CastMember.color`.
- **Label and color modes are Postgres enums** (`label_mode`, `color_mode`), defaulting to `name` and `dancer`.
- **The view controls (Labels, Color by, Guides) sit in a light row above the stage**, not over it, so they don't crowd a phone-width stage.
- **Removing a dancer from the roster sets `CastMember.dancerId` to null** (`onDelete: SetNull`). The API returns `dancer: null`, and the UI shows "Open spot" (a dashed ring on stage).
- **Giving a spot to another dancer (B5)** is a `PATCH` with `dancerId`. The spot keeps its id, role and positions. The API allows it for any cast member, so replacing a dancer works later without a change; the UI offers it only for open spots.
- **Roles** are trimmed, blank means no role, and the maximum is 40 characters.
- **Cast panel:** a 300px right sidebar from 900px wide up. Below that it stacks under the stage, capped at 45dvh, until the iPhone bottom sheet comes in plan 8.2. Buttons are the regular 44px size, not the design's 36px small one, to keep `touch-min`.
- **Circles** are HTML placed over the SVG plan by percentage, so they keep their token size: `dancer-dot-ipad` 40px, `dancer-dot-phone` 26px under 600px wide. Dancers off the floor are at 80% opacity.

## API

All routes are under `/api/schools/:schoolId`:

- `GET /dances/:danceId/cast` → `{ cast: CastMember[] }`
- `POST /dances/:danceId/cast` `{ dancerId, role? }` → 201 `{ castMember, position }` (400 for another school's dancer, 404 for another school's dance, 409 if already cast)
- `PATCH /dances/:danceId/cast/:castMemberId` `{ role?, dancerId? }` → `{ castMember }` (400 for another school's dancer, 409 if the new dancer is already cast)
- `DELETE /dances/:danceId/cast/:castMemberId` → 204
- `GET /dances/:danceId/figures` → `{ figures: [{ id, order, name, positions: [{ castMemberId, x, y }] }] }`
