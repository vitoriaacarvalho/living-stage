# 1.2 — Sign in

Requirement: **A1.** A user can sign up and sign in with email and password.

Done when: a user can sign up with email and password, sign in, and sign out.

Screens: `Access` (load the `living-stage-design` skill).

## Decisions

- **Email and password only.** No third-party sign-in (Google, Apple) for now.
- **No email sending yet.** No email verification and no password reset for now. Both come back with A3 (invites by email), which needs an email sender anyway. Until then, a forgotten password can't be recovered.
- **Sign-up signs you in.** Better Auth's default `autoSignIn` after sign-up.
- **Passwords.** Better Auth's defaults: 8 to 128 characters, hashed with scrypt.
- **Same origin.** Better Auth runs inside Express under `/api/auth/*`. In development the Vite proxy forwards `/api` to the API, so the browser only sees the web origin and the session cookie is first-party (safe from Safari ITP on iPad and iPhone). In production, web and API are served from one domain.
- **Database sessions with a cookie cache.** Sessions are stored in Postgres. A signed cookie caches the session for 5 minutes to skip the database lookup on most requests. Trade-off: a revoked session can stay valid for up to 5 minutes.
- **No IP addresses stored.** An IP address is personal data under LGPD, so a `databaseHooks.session.create.before` hook sets `session.ipAddress` to null. `advanced.ipAddress.disableIpTracking` was rejected because it also turns off rate limiting, which only keeps IPs in memory.

## Data model

Better Auth's core tables, generated into `apps/backend/prisma/schema.prisma`:

- `User`: id, name, email, emailVerified, image, createdAt, updatedAt
- `Session`: id, userId, token, expiresAt, ipAddress, userAgent
- `Account`: id, userId, providerId (`credential`), accountId, password hash, tokens
- `Verification`: id, identifier, value, expiresAt (unused until email verification and reset come back)

`User.language` (from `docs/plan.md` §5) is added in plan 8.3 (J2), not here.

## Configuration

Backend env vars (`apps/backend/.env`, never committed; keys listed in `.env.example`):

| Variable | Dev value |
|---|---|
| `BETTER_AUTH_SECRET` | random 32+ byte string (`openssl rand -base64 32`) |
| `BETTER_AUTH_URL` | `http://localhost:5173` (the web origin, because of the proxy) |

## Slices

Each slice is one commit, starting with `A1:`.

Backend:

1. This plan.
2. Install `better-auth` and write the auth config: Prisma adapter, email and password, cookie cache, env vars.

Frontend:

   3. Sign-up form, with Better Auth error codes mapped to pt-BR messages.
   4. `App` switches on `useSession()`: no session shows `Access`, a session shows the app. No router yet.

`Access` shipped unstyled, with hard-coded pt-BR copy. Plan 1.2a switches it to English, plan 1.6a styles it to the design, and plan 8.3 adds pt-BR back through i18n.

## Out of scope

- Third-party sign-in (Google, Apple). If it comes back before email verification, disable automatic account linking: otherwise someone could register another person's email with a password and keep access once the real owner signs in with that provider.
- Email verification and password reset (come back with A3).
- Magic links, passkeys, two-factor.
- Changing email or password from a settings page.
- Schools and memberships (plan 1.3).
- Language preference (plan 8.3).
