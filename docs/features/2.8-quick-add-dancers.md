# 2.8 — Quick-add dancers

Requirement: **B7** (add a new dancer from a dance's "Add to cast" panel; she joins the roster and the cast at once).

Done when: From a dance's "Add to cast" panel, search the roster and add a new dancer who is not in it yet; she lands in the roster and in the cast without leaving the dance.

Screens: `CastList`, the "Add to cast" panel of the dance editor (load the `living-stage-design` skill). The design has no search or new-dancer control in this panel yet; this plan adds them with the existing `TextField`, the dancer color swatches and the `plus` icon.

## Why

A teacher working in a dance often finds that a dancer is not in the roster yet. Today they have to leave the dance, add the dancer on the Dancers screen and come back. The Dancers screen keeps its "Add dancer"; this plan adds a second way in, from where the teacher already is.

## Decisions

- **It lives in the "Add to cast" panel** (`CastPicker`), not in a new dialog. The panel stays open while dancers are added, as it does today.
- **The panel gets a search field**, "Search by name", above the list. It filters the dancers not in this dance with `matchesName` (ignores case and accents), like the roster screen. It shows even when every roster dancer is already cast, since that is when a new dancer is most likely needed.
- **A "New dancer" row sits at the top of the list.** With an empty search it reads "New dancer". With a search that matches no roster dancer's name exactly (ignoring case and accents, cast or not), it reads "Add “Ana” as a new dancer" and is shown above any partial matches. With an exact match it is hidden, so the teacher picks the dancer who is already there.
- **The row opens a short form in the panel**: Name (filled from the search, trimmed) and the optional color swatches, the same fields and rules as the roster's `DancerForm` (name required, up to its max length; color 1–12 or none). No role: it is set on the cast member afterwards, as today. Cancel goes back to the list with the search kept.
- **Saving creates and casts in one step.** The browser calls the existing routes in turn: `POST /dancers`, then `POST /dances/:danceId/cast` with no role. The new dancer waits in the left wing like any newly cast dancer. The panel then goes back to the list with the search cleared, ready for the next name.
- **No new API route.** If the dancer is created but casting fails, she stays in the roster (no harm done), the panel goes back to the list with the same "Could not add Ana. Try again." as a failed pick, and she is in the list to tap. If creating fails, the form stays open with "Could not save the dancer. Try again."
- **"Give the spot to" gets the same search and "New dancer" row**, since both pickers share one list: a new dancer saved there is given the open spot instead of a new one.
- **A full cast hides it all.** At 40 dancers (E9) the panel shows its "A dance holds up to 40 dancers" note only, with no search and no "New dancer", since a new dancer could not be cast.
- **The roster in the panel stays current.** The new dancer is added to the panel's `useDancers` list, so she shows on the Dancers screen and in the next picker without a reload.

## API

No new routes. It uses:

- `POST /api/schools/:schoolId/dancers` `{ name, color }` → 201 `{ dancer }`
- `POST /api/schools/:schoolId/dances/:danceId/cast` `{ dancerId, role: null }` → 201 `{ castMember, positions }`

## Slices

1. ✅ Search field in the "Add to cast" panel, filtering the dancers not in this dance.
2. ✅ "New dancer" row and its name and color form in the panel; saving creates the dancer, casts her and goes back to the list. Includes the two failure messages.
3. ✅ From a search with no exact match, the row offers "Add “Ana” as a new dancer" and opens the form with the name filled.
4. ⬜ Check "Done when" in the browser at iPhone, iPad and desktop sizes, then mark B7 and 2.8.

## Out of scope

- Setting a role in the quick form, editing or removing roster dancers from the editor, and a single create-and-cast route.
